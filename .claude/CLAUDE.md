# Default workflow: plan here, execute on Haiku executors

These rules apply to the main (top-level) session only. If you are a subagent/executor working from a brief, do the work yourself: never dispatch further subagents and don't create or update tasks.

## Plan with a task list (a DAG)
- For any non-trivial request (more than a quick answer or a one-line edit), break the work into tasks with TaskCreate (load TaskCreate/TaskUpdate via ToolSearch if deferred): one task per dispatchable unit of work. Keep it updated: in_progress when starting/dispatching, completed only after the report passes its acceptance checks. Add follow-up tasks for anything left open; delete superseded ones.
- Make the task list a DAG. After creating tasks, wire only real dependencies with TaskUpdate `addBlockedBy` (B needs A's output, or A and B touch the same files); never add edges for mere preference. A task is ready when it is pending, unowned, and all its blockers are completed.
- Tasks that are yours or the user's (reviews, decisions, the final report) get `metadata: {"dispatch": false}`.
- For planned work, use plan mode. The plan file must contain exactly one ```tasks fenced JSON block: an array of tasks, or an object {"serial_reason": "...", "tasks": [...]} (serial_reason is needed for a pure chain of 4 or more dispatchable tasks). Each task has `id`, `subject`, `writes` (paths or globs it touches, `[]` if none), optional `needs` ({other_id: reason}) and optional `dispatch` (false for tasks that are yours or the user's). Example: `[{"id":"A","subject":"Edit parser","writes":["src/parser.py"]},{"id":"B","subject":"Add parser tests","writes":["tests/test_parser.py"],"needs":{"A":"tests use the new API"}},{"id":"R","subject":"Final report","writes":[],"dispatch":false}]`. plan-gate.py computes the edges from `needs` and from overlapping `writes`, so declare files honestly. After approval, create each task with `metadata.plan_id` exactly as the hook's context says. The plan must also contain exactly one ```files fenced block: a directory tree of every file the plan writes, laid out as in the project, so the user can review scope and modularity. Directories end in `/`, and each file line is tagged with the task ids that write it (e.g. `src/` then `  parser.py  [A]  new` under it; `docs/  [C]` covers a whole-directory write by task C). The tree must match the tasks' `writes` exactly. The hook's deny message prints the expected tree.
- Dispatch by readiness: send every ready task's Agent call in ONE message, each `description` naming its task as `· #<id>` or `task #<id>` (e.g. "Qorvax Tel · #3 fix"). task-gate auto-claims the named task (in_progress, owner = subagent_type) when that executor owns no in_progress task, so no TaskUpdate is needed. The UI task list still shows it pending until you mark it completed. An explicit TaskUpdate (in_progress, owner = executor) in a prior message still works. Never dispatch ready tasks one per turn. When a report passes its checks, mark the task completed and dispatch everything the hook reports as newly ready the same way.

## Dispatch work to Haiku executors
- Don't do implementation work yourself (edits, commands, test runs, bulk searches). Dispatch it with the Agent tool to an executor from this pool (as `subagent_type`): `qorvax-tel`, `zyrene-vosk`, `thal-ummir`, `kreeva-osh`, `vexlor-ain`, `nyxa-prell`, `oomrak-zhee`, `xilth-varo`, `juun-ketrax`, `plimm-oraxi`. They are defined in `~/.claude/agents/<name>.md` and run on Haiku at medium effort. The task's owner must equal the executor name.
- Every executor dispatch needs a task: TaskCreate it, then name it in the Agent description as `· #<id>`. There is no single-dispatch exemption.
- Executors default to medium effort (agent frontmatter). Dispatch with `effort: "high"` for debugging or open-ended investigation, multi-file changes where the executor must infer how code fits together, or a retry after a report failed its acceptance checks.
- Parallel executors are encouraged for independent work, one Agent call each in the same message, each with a distinct name and its own brief. Work that touches the same files goes to one executor or runs in sequence. Executors may only change files inside a git worktree (enforced by `subagent-worktree.py`): dispatch with `isolation: "worktree"`, or name a worktree in the brief or have the executor create one with `git -C <repo> worktree add <repo>/.claude/worktrees/<name> -b <branch>`. Scratch output goes in `$CLAUDE_JOB_DIR/tmp`. Parallel executors each get their own worktree.
- Executors run up to `pool_size` at once (default 8; `harness.local.json` or env `TASK_GATE_POOL_SIZE`). When slots are free, dispatch every ready task in one message, one Agent call each, with `run_in_background: true` while other tasks are ready: task-gate.py denies a foreground executor dispatch then (`require_background` in the local config, default true; env `TASK_GATE_REQUIRE_BACKGROUND=0` turns it off; always off when `LOCAL_DISPATCH` is set). dispatch-stop.py blocks ending a turn while slots are free and tasks are ready (off in local and hybrid modes).
- Every brief is self-contained (Haiku has no context from this conversation): goal, files, exact steps, **acceptance checks**, and a report format. Every brief also includes the global no-regression checks: the full verify/test failure count must not rise, and no feature is dropped, no fit loosened and no check weakened to make a test pass. A retry brief also includes the exact failing command output and a one-concern scope. End with an explicit format, e.g. "Report in under 150 words: files changed, pass/fail per acceptance check, errors or blockers. No code dumps, no restating the task."
- Stay the orchestrator: review reports, integrate/merge worktree results, resolve conflicts, and verify each report against its acceptance checks before telling the user it's done. Don't trust a "done" without checking.
- Escalation ladder (after a Haiku round fails its acceptance checks):
  1. **Split first.** If the report says "stopped at scoping" / "no edits", or the task spans more than ~10 files or more than one concern, do not escalate: create 2-3 smaller Haiku tasks (wire them into the DAG) and dispatch those.
  2. **Verification-only failures** (pixdiff, counts, screenshots): retry Haiku once at `effort: "high"` with the exact failing output pasted into the brief.
  3. **Coupled or debug failures** (the cause is not clear from the report): set `escalate_reason` and `escalate_class` (`scale`, `verify`, `debug` or `coupled`) in the failed task's metadata. TaskCreate a diagnose task owned by `diagnoser-1` with `metadata.diagnoses` set to the failed task's id (do not set `dispatch: false`; it is dispatched). Dispatch `Agent(subagent_type="diagnoser-1")` with `model` and `effort` omitted, giving it the failed task's brief, the exact failing output and the files involved. When it returns, re-dispatch the failed task to Haiku at `effort: "high"`, with the diagnoser's `## Fix spec` pasted into the brief and its `## Checks` as the acceptance checks. The failed task needs at least one Haiku round before it can be diagnosed.
  4. **Second failure after a spec**: one more diagnosis, with the prior spec and the new failing output in the brief. If that round also fails, or the diagnoser returns `DIAGNOSIS-VERDICT: NEEDS-USER`, stop and ask the user.
  5. Each `escalate_reason` buys one round (the hook clears it). Cap: 3 executor rounds per task, enforced by task-gate; then stop and ask the user, and only after their OK set `metadata.allow_extra_rounds`. Diagnoses cap at 2 per task and 4 per session (`diagnose_gate`). Sonnet executors return only when `model_gate.sonnet_fallback` is true in the local config (kill switch for the old ladder).
- Do the work directly (no subagent) only when it's trivial, needs the full conversation context, or is faster than writing a brief — within what the read-only hook allows.

## Pull request review gate
- Before any PR leaves draft (`gh pr ready`), it needs an Opus review of its current head commit. Create a task "Opus review <owner/repo>#N", blocked by the task that produced the PR, owned by `pr-reviewer-1`, `pr-reviewer-2` or `pr-reviewer-3`; dispatch it with Agent(subagent_type="pr-reviewer-<n>") with `model` and `effort` omitted (the haiku/medium rule above is for executors only), and give it the PR URL and the local checkout path. The reviewer runs the code-review skill and ends with a REVIEW-VERDICT line. The "mark ready" task is blocked by the review task. On CHANGES: a fix task for an executor, then a new review task (any push changes the head SHA and voids the approval). The loop ends at the first APPROVE. Nits never block: a reviewer whose findings are all nits (style, naming, comments, minor/speculative edge cases, non-regression polish) returns APPROVE with the nits listed, and you do NOT dispatch a fix task for those nits; list them for the user in the final report instead. Cap: at most 3 review rounds per PR; if the 3rd review returns CHANGES (the reviewer prints CAP REACHED), stop and ask the user instead of dispatching another fix. Hooks enforce this: ready-gate.py denies `gh pr ready` without an APPROVE for the head SHA and denies `gh pr create` without `--draft`; review-record.py records the verdict; task-gate.py denies a reviewer dispatched on a non-Opus model.
- Rounds 2 and 3 are re-reviews: give the reviewer the previously reviewed SHA and the previous round's findings so it reviews only the fix diff.

## Main-session Bash (token budget)
- The main-readonly hook rejects shell shapes that write or expand, and each rejection wastes a full-context turn; its deny message now states the reason. Quotes are respected: `$x`, `{}` or `>` inside single quotes are fine (e.g. `jq '.a > 1'`). Allowed: read-only commands (`ls`, `cat`, `head`, `wc`, `grep`, `find -name`, `jq`, `sed -n`, `git -C <path> log`), commands matching `main_allow_commands` globs from harness.local.json, scripts run from job tmp dirs (`~/.claude/jobs/<id>/tmp/` or `$CLAUDE_JOB_DIR/tmp/`), `&&`, `||` or `;` chains where every part is allowed, a read command piped into `head`/`grep`/`sort`/`uniq`, and `2>/dev/null`, `2>&1`, `&>/dev/null`. The `main_allow_commands` and job-tmp rules apply to the main session only, never to reviewers. Rejected: other redirects, `&` backgrounding, `$(`, backticks, `${` or `$var` outside single quotes, `echo`, `diff`, `python3 -c`, and any write. Don't send a rejected shape.
- Read files with the Read tool. For several independent reads, send several Bash/Read calls in one message: they run in parallel and cost no extra turn.
- Keep big reads out of main: every tool result stays in main's context until the next compaction, so anything likely over ~200 lines or ~10k tokens (whole large files, logs, test/build output, multi-file sweeps) goes to `Explore` (search) or an executor (run and summarize), which returns only the findings. Main reads targeted slices (Read with `offset`/`limit`, `grep -n … | head`). Small reads that decide the next step stay in main.
- If a read needs a script, `python -c` or a rejected shape, fold it into an executor brief you are already sending, or skip it; dispatch an executor just for a read only when the answer changes what you do next.

## Enforcement (hooks in ~/.claude/settings.json)
- `main-readonly.py`: main can't Write/Edit/Bash except plans, memory, and job tmp dirs. Kill switch `CLAUDE_MAIN_WRITE=1`. The main session runs on Opus and is read-only. Reviewer subagents (pr-reviewer-*, opus-reviewer) and diagnosers (diagnoser-*) get the same read-only rules as main, without the `main_allow_commands` and job-tmp exceptions.
- `subagent-worktree.py`: a subagent may Write/Edit, or run a shell command that changes something, only inside a linked git worktree or a scratch dir ($CLAUDE_JOB_DIR/tmp, the system temp dir). Read-only commands and `git worktree add` work anywhere. Exempt types: Explore, Plan, claude-code-guide, statusline-setup, opus-reviewer, pr-reviewer-*, diagnoser-*. Sessions matched by `exempt_env` in the local config are exempt too; `subagent_allow_commands` lists commands allowed in any directory. Kill switch `CLAUDE_SUBAGENT_ANYWHERE=1`. Known gap: the Monitor tool is not gated (only Bash and PowerShell are).
- `task-gate.py`: an Agent dispatch needs an in_progress, unblocked task owned by that `subagent_type`, with no single-dispatch exemption; rejects cycles, in_progress on a blocked task, and one executor owning two in_progress tasks; enforces the executor pool cap (`pool_size`, default 8) and tracks running executors through PreToolUse, PostToolUse and SubagentStop; denies an executor dispatch without `run_in_background: true` while other tasks are ready (see Dispatch); after a completion it lists ready tasks. Exempt types: web-fetch, claude-code-guide, Explore (Plan is gated like any other non-executor type); exempt types run on Haiku only (model omitted or haiku), and `model_gate.allow_types` entries need an explicit `model: haiku` (omitted is not enough). `CLAUDE_MAIN_WRITE=1` does not lift the model gate, and executors may only use haiku (never opus, fable or unknown models; sonnet only with `model_gate.sonnet_fallback: true`). Model gate (main session only): `subagent_type` must be an executor (an agent file with `model: haiku` in ~/.claude/agents), a reviewer, a diagnoser (`diagnoser-1`), an exempt type, or listed in `model_gate.allow_types`; any other type (general-purpose, fork, claude, unknown) is denied. An executor's `model` other than omitted or haiku is denied unless `model_gate.sonnet_fallback` is true; then it needs escalation proof on the task: an earlier allowed Haiku round, a non-empty `metadata.escalate_reason`, a valid `metadata.escalate_class` (scale|verify|debug|coupled), and a model in `model_gate.escalate_to` (default sonnet; opus is never allowed for executors). The reason and class are cleared after one allowed round, and a task is capped at `model_gate.max_rounds` (default 3) executor rounds unless `metadata.allow_extra_rounds` is set; otherwise denied with the reason (logged `model-gate=type` or `model-gate=escalation`). Each allowed escalation is logged to the completion log as `kind: escalation`. Kill switch `CLAUDE_REQUIRE_TASK=0` disables only the DAG ownership gate, round cap and task-based escalation proof; Haiku executors still pass, while Sonnet and Opus executors and any Agent call from a subagent stay denied. Reviewers (`pr-reviewer-*`, `opus-reviewer`) and diagnosers (`diagnoser-*`) must use Opus (model omitted or `opus`). A diagnoser dispatch needs a diagnose task owned by its name with `metadata.diagnoses` set to a failed task that has at least one Haiku round and a non-empty `escalate_reason` and valid `escalate_class`; the gate clears the reason and class on dispatch. Caps: `diagnose_gate.max_per_task` (default 2) and `diagnose_gate.max_per_session` (default 4). Diagnosers run one at a time. SendMessage to a diagnoser is denied (one-shot). Auto-claim: an Agent call whose description (never the prompt) contains `· #<id>` (middle dot, optional spaces) or `task #<id>` (case-insensitive) claims that ready task for its executor; any other `#<id>` names nothing. A named task that is not ready is denied, with the reason. A claim whose call never reaches PostToolUse can be retaken only by the same executor (its re-dispatch); any other executor must reset it with TaskUpdate status pending, owner "".
- `ready-gate.py` (PreToolUse on Write, Edit, MultiEdit, NotebookEdit, Bash, PowerShell; main and subagents): denies `gh pr ready` unless the latest REVIEW-VERDICT for that PR's head SHA is APPROVE, denies `gh pr create` without `--draft` or `-d`, denies GraphQL `markPullRequestReadyForReview` (use `gh pr ready`), stops a PR after 3 CHANGES rounds, and blocks writes to `pr-reviews.jsonl`. Kill switch `CLAUDE_SKIP_READY_REVIEW=1`. It ignores `exempt_env` (on in `CLAUDE_LOCAL`).
- `review-record.py` (SubagentStop, `opus-reviewer` and `pr-reviewer-*` only): records the final REVIEW-VERDICT line (APPROVE or CHANGES) in `~/.claude/hooks/state/pr-reviews.jsonl`. A reviewer that ends without a verdict line is blocked once to add one; ABSTAIN records nothing.
- `diagnose-record.py` (SubagentStop, `diagnoser-*` only): checks the diagnoser's output contract: headings `## Root cause`, `## Fix spec` and `## Checks`; last line `DIAGNOSIS-VERDICT: SPEC` or `DIAGNOSIS-VERDICT: NEEDS-USER`; at most 8000 characters; no code block over 20 lines. `plan-gate.py` treats `diagnoser-*` like the reviewers.
- `plan-gate.py`: PreToolUse ExitPlanMode denies leaving plan mode until the plan's ```tasks block is valid and its DAG passes the limits (no cycles, at most `plan_max_writes` write entries per dispatchable task, and a pure chain of 4+ dispatchable tasks needs a `serial_reason`), and the ```files tree matches the tasks' writes (`plan_require_files`, default true). PostToolUse ExitPlanMode saves the DAG and lists the TaskCreate and addBlockedBy calls. PreToolUse Agent/Task and TaskUpdate deny dispatch and edges that do not match the saved plan. A plan retires after `plan_ttl_sec` or when an abandon task exists (the hook's deny message says how to create one). Kill switch `CLAUDE_PLAN_GATE=0`.
- `dispatch-stop.py` (Stop): blocks ending the turn, once per stop, while executor slots are free and ready tasks wait. It does nothing for subagents, and is off when `CLAUDE_DISPATCH_STOP=0`, `CLAUDE_REQUIRE_TASK=0`, `CLAUDE_MAIN_WRITE=1`, `CLAUDE_LOCAL` or `LOCAL_DISPATCH` is set.
- `agent-names.py`: names each subagent (executors get their own name; others get a round-robin name). Kill switch `CLAUDE_AGENT_NAMES=0`.
- `result-capture.py` (Stop): appends each `result:` line of the final message to `~/.claude/hooks/state/completed-work.jsonl` (deduped per session); `task-gate.py` appends a `"kind": "task"` line there on each task completion.
- `agent-budget.py`: subagent tool-call cap. Soft 150: the call is denied once with a wrap-up message, then allowed until hard 200. Reviewers (`pr-reviewer-*`, `opus-reviewer`) 80/110; diagnosers (`diagnoser-*`) 40/60. Config key `agent_budget` in `harness.local.json`; env `AGENT_BUDGET_SOFT`/`AGENT_BUDGET_HARD` override. Kill switch `CLAUDE_AGENT_BUDGET=0`.
- `handoff-nudge.py` (SessionStart, matcher `compact`): counts compactions per session. From the 3rd it nudges toward a handoff in a fresh session; if the previous compaction was under 20 min ago (from the 2nd) it also flags thrash and says to move big reads to `Explore`/executors. `HANDOFF_NUDGE_AFTER` sets the count threshold, `HANDOFF_NUDGE_RAPID_MIN` the rapid window. Kill switch `CLAUDE_HANDOFF_NUDGE=0`.
- `statusline.py`: one-line status line: model and effort, context bar, prompt-cache state, cost, wall time.
- Local mode: `CLAUDE_LOCAL=1` (set by claude-local) exempts main-readonly and task-gate via `exempt_env` in harness.local.json, and `local-mode.py` (SessionStart) tells the model to work directly. The executor/task/review rules above don't apply in local mode. Hybrid: `LOCAL_DISPATCH=1` or `subagents` (claude-hybrid; `claude` shim in .bashrc) keeps all rules on but runs haiku executors on the local model; `LOCAL_DISPATCH=all` (claude-local-all) runs the main session and every subagent on the local model with no Anthropic fallback. Dispatch local executors one at a time.
